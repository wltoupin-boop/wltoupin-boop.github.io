## 1. Overview

This document defines the complete PostgreSQL schema for the Cell & Gene Therapy Tracking Platform. The schema is managed via Alembic migrations and versioned in source control. All DDL changes must be made through migration scripts; manual schema modification in production is prohibited.

**Database:** `cgt_platform`  
**Schema:** `public` (all tables reside in the default schema)  
**Character Encoding:** UTF-8  
**Collation:** `en_US.UTF-8`  
**Timezone:** UTC (all timestamps stored in UTC)

---

## 2. Conventions

- All primary keys are UUID v4 generated by the application layer (using Python's `uuid.uuid4()`). The `gen_random_uuid()` PostgreSQL function is used as a default for any rows inserted directly via SQL.
- All timestamps are `TIMESTAMPTZ` (timestamp with time zone), stored in UTC.
- `created_at` columns are set on INSERT and never updated.
- `updated_at` columns are automatically maintained by a trigger (see Section 4).
- Soft deletes are preferred over hard deletes for entity tables; records are deactivated via boolean flags rather than removed.
- JSONB is used for flexible, schema-less nested data. Fields using JSONB are documented with their expected structure in comments.
- All foreign key constraints include explicit `ON DELETE` behavior.
- Index names follow the pattern: `idx_{table}_{column(s)}`.
- Unique constraint names follow the pattern: `uq_{table}_{column(s)}`.
- Foreign key constraint names follow the pattern: `fk_{table}_{referenced_table}`.

## 4. Utility Functions & Triggers

```sql
-- ============================================================
-- UTILITY: auto-update updated_at on any row modification
-- Apply this trigger to every table with an updated_at column.
-- ============================================================

CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$;

-- Helper macro: creates the trigger on a given table.
-- Usage: SELECT create_updated_at_trigger('table_name');
CREATE OR REPLACE FUNCTION create_updated_at_trigger(target_table TEXT)
RETURNS VOID
LANGUAGE plpgsql
AS $$
BEGIN
    EXECUTE format(
        'CREATE TRIGGER trg_%s_updated_at
         BEFORE UPDATE ON %I
         FOR EACH ROW EXECUTE FUNCTION set_updated_at();',
        target_table, target_table
    );
END;
$$;
```

## 5. Table Definitions

### 5.1 `institutions`

Represents a hospital, academic medical center, health system, or specialty program subscribing to the platform.

```sql
CREATE TABLE institutions (
    id                  UUID            PRIMARY KEY DEFAULT gen_random_uuid(),

    -- Identity
    name                TEXT            NOT NULL,
    type                institution_type NOT NULL,

    -- Location
    city                TEXT,
    state               TEXT,
    country             TEXT            NOT NULL DEFAULT 'US',

    -- Flexible structured contact and configuration data
    -- contact_info expected shape:
    --   { "primary_contact": { "name": str, "email": str, "phone": str },
    --     "it_contact": { "name": str, "email": str } }
    contact_info        JSONB           NOT NULL DEFAULT '{}',

    -- settings expected shape:
    --   { "notification_defaults": { "email": bool, "in_app": bool },
    --     "enabled_modules": ["watchlists", "readiness"],
    --     "default_disease_categories": ["hematologic_malignancy"] }
    settings            JSONB           NOT NULL DEFAULT '{}',

    -- Status
    is_active           BOOLEAN         NOT NULL DEFAULT TRUE,
    subscription_tier   TEXT,                          -- 'trial', 'standard', 'enterprise'
    subscription_expires_at TIMESTAMPTZ,

    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

-- Trigger
SELECT create_updated_at_trigger('institutions');

-- Indexes
CREATE INDEX idx_institutions_type       ON institutions (type);
CREATE INDEX idx_institutions_is_active  ON institutions (is_active);
CREATE INDEX idx_institutions_country    ON institutions (country);

-- Full-text search on institution name
CREATE INDEX idx_institutions_name_fts
    ON institutions USING GIN (to_tsvector('english', name));
```

### 5.2 `users`

Represents an authenticated user of the platform. Linked to Firebase Authentication via `firebase_uid`.

```sql
CREATE TABLE users (
    id                  UUID            PRIMARY KEY DEFAULT gen_random_uuid(),

    -- Firebase identity linkage
    firebase_uid        TEXT            NOT NULL,

    -- Profile
    email               TEXT            NOT NULL,
    name                TEXT            NOT NULL,

    -- Authorization
    role                user_role       NOT NULL DEFAULT 'user',
    institution_id      UUID            REFERENCES institutions (id)
                                            ON DELETE SET NULL,

    -- preferences expected shape:
    --   { "notification_email": bool,
    --     "notification_in_app": bool,
    --     "default_dashboard": "personal" | "institution",
    --     "disease_category_filters": ["hematologic_malignancy"],
    --     "timezone": "America/New_York" }
    preferences         JSONB           NOT NULL DEFAULT '{}',

    -- Status
    is_active           BOOLEAN         NOT NULL DEFAULT TRUE,
    last_login_at       TIMESTAMPTZ,

    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

-- Triggers
SELECT create_updated_at_trigger('users');

-- Indexes
CREATE UNIQUE INDEX uq_users_firebase_uid   ON users (firebase_uid);
CREATE UNIQUE INDEX uq_users_email          ON users (email);
CREATE        INDEX idx_users_institution   ON users (institution_id);
CREATE        INDEX idx_users_role          ON users (role);

-- Foreign key constraint label
ALTER TABLE users
    ADD CONSTRAINT fk_users_institutions
    FOREIGN KEY (institution_id) REFERENCES institutions (id) ON DELETE SET NULL;
```

### 5.3 `therapies`

The core entity of the platform. Stores a normalized record for each tracked cell or gene therapy.

```sql
CREATE TABLE therapies (
    id                          UUID                PRIMARY KEY DEFAULT gen_random_uuid(),

    -- ── Identity ────────────────────────────────────────────────────────────
    product_name                TEXT                NOT NULL,   -- Canonical name used throughout platform
    generic_name                TEXT,
    brand_name                  TEXT,                           -- Post-approval trade name
    manufacturer                TEXT,
    sponsor                     TEXT,                           -- Clinical trial sponsor (may differ from manufacturer)

    -- ── Classification ──────────────────────────────────────────────────────
    therapy_type                therapy_type,
    vector_platform             TEXT,               -- e.g., "AAV9", "Lentiviral", "CD19 CAR"
    disease                     TEXT,               -- Specific disease name (free text)
    disease_category            disease_category,
    indication_details          TEXT,               -- Detailed indication description from label/protocol

    -- ── Population Flags ────────────────────────────────────────────────────
    pediatric_relevance         BOOLEAN             NOT NULL DEFAULT FALSE,
    rare_disease                BOOLEAN             NOT NULL DEFAULT FALSE,

    -- ── Regulatory Designations ─────────────────────────────────────────────
    orphan_drug                 BOOLEAN             NOT NULL DEFAULT FALSE,
    breakthrough_therapy        BOOLEAN             NOT NULL DEFAULT FALSE,
    rmat                        BOOLEAN             NOT NULL DEFAULT FALSE,  -- Regenerative Medicine Advanced Therapy
    fast_track                  BOOLEAN             NOT NULL DEFAULT FALSE,
    priority_review             BOOLEAN             NOT NULL DEFAULT FALSE,
    accelerated_approval        BOOLEAN             NOT NULL DEFAULT FALSE,

    -- ── Clinical Development ─────────────────────────────────────────────────
    clinical_phase              clinical_phase,

    -- trial_identifiers: array of objects
    -- [{ "nct_number": "NCT12345678", "trial_name": str, "status": str, "phase": str }]
    trial_identifiers           JSONB               NOT NULL DEFAULT '[]',
    trial_status                TEXT,               -- Summarized trial status (e.g., "Enrolling", "Completed")
    primary_completion_date     DATE,
    study_completion_date       DATE,

    -- expected_readout_dates: array of objects
    -- [{ "event": str, "expected_date": date_str, "source": str, "note": str }]
    expected_readout_dates      JSONB               NOT NULL DEFAULT '[]',

    -- key_milestones: array of objects
    -- [{ "milestone": str, "date": date_str, "is_completed": bool, "source": str }]
    key_milestones              JSONB               NOT NULL DEFAULT '[]',

    -- ── Regulatory & Approval ────────────────────────────────────────────────
    regulatory_status           TEXT,               -- Free-text overall regulatory summary
    fda_approval_status         fda_approval_status NOT NULL DEFAULT 'not_submitted',
    approval_date               DATE,
    approval_type               TEXT,               -- "Full Approval" | "Accelerated Approval"
    label_limitations           TEXT,               -- Key label limitations and warnings summary
    required_confirmatory_studies TEXT,             -- For accelerated approval: confirmatory study requirements

    -- post_marketing_commitments: array of objects
    -- [{ "commitment": str, "due_date": date_str, "status": str }]
    post_marketing_commitments  JSONB               NOT NULL DEFAULT '[]',

    pdufa_date                  DATE,               -- Prescription Drug User Fee Act goal date
    advisory_committee_date     DATE,               -- AdCom meeting date if scheduled

    -- relevant_fda_documents: array of objects
    -- [{ "type": "BLA"|"Label"|"REMS"|"ReviewMemo", "url": str, "date": date_str, "title": str }]
    relevant_fda_documents      JSONB               NOT NULL DEFAULT '[]',

    -- ── Intelligence & News ──────────────────────────────────────────────────
    -- recent_news_items: array of objects
    -- [{ "title": str, "source": str, "url": str, "published_date": date_str,
    --    "summary": str, "relevance_score": 0-100 }]
    recent_news_items           JSONB               NOT NULL DEFAULT '[]',

    -- ── Epidemiology ────────────────────────────────────────────────────────
    -- All prevalence fields follow this shape:
    -- { "estimate": int, "unit": "patients", "source": str, "year": int, "notes": str }
    global_prevalence           JSONB,
    national_prevalence         JSONB,
    pediatric_prevalence        JSONB,

    -- addressable_population: estimated eligible patient population for this therapy
    -- { "estimate": int, "methodology": str, "source": str, "year": int }
    addressable_population      JSONB,

    -- ── AI-Generated Content ─────────────────────────────────────────────────
    ai_plain_summary            TEXT,               -- Plain-language summary for clinical users
    ai_operational_summary      TEXT,               -- Operationally focused summary for pharmacy/ops
    ai_summary_generated_at     TIMESTAMPTZ,        -- When the current AI summaries were generated
    ai_summary_model_version    TEXT,               -- Claude model version used for summary
    ai_summary_prompt_version   TEXT,               -- Prompt template version used

    -- ── Data Quality ────────────────────────────────────────────────────────
    -- Score 0-100 reflecting coverage and consistency of source data
    source_confidence_score     SMALLINT            CHECK (source_confidence_score BETWEEN 0 AND 100),

    -- data_sources: array of objects
    -- [{ "source_type": str, "last_fetched": datetime_str, "record_count": int }]
    data_sources                JSONB               NOT NULL DEFAULT '[]',

    -- ── Record Lifecycle ────────────────────────────────────────────────────
    last_updated                TIMESTAMPTZ         NOT NULL DEFAULT NOW(),  -- Last meaningful data change
    is_active                   BOOLEAN             NOT NULL DEFAULT TRUE,
    needs_human_review          BOOLEAN             NOT NULL DEFAULT FALSE,  -- Flagged for review before display

    created_at                  TIMESTAMPTZ         NOT NULL DEFAULT NOW(),
    updated_at                  TIMESTAMPTZ         NOT NULL DEFAULT NOW()
);

-- Trigger
SELECT create_updated_at_trigger('therapies');

-- ── Indexes ──────────────────────────────────────────────────────────────────

-- Primary lookups
CREATE INDEX idx_therapies_disease_category     ON therapies (disease_category);
CREATE INDEX idx_therapies_clinical_phase       ON therapies (clinical_phase);
CREATE INDEX idx_therapies_fda_approval_status  ON therapies (fda_approval_status);
CREATE INDEX idx_therapies_therapy_type         ON therapies (therapy_type);
CREATE INDEX idx_therapies_pdufa_date           ON therapies (pdufa_date) WHERE pdufa_date IS NOT NULL;
CREATE INDEX idx_therapies_approval_date        ON therapies (approval_date) WHERE approval_date IS NOT NULL;
CREATE INDEX idx_therapies_is_active            ON therapies (is_active);
CREATE INDEX idx_therapies_needs_human_review   ON therapies (needs_human_review) WHERE needs_human_review = TRUE;
CREATE INDEX idx_therapies_manufacturer         ON therapies (manufacturer);

-- Designation flag filters (partial indexes for performance on TRUE values)
CREATE INDEX idx_therapies_rmat                 ON therapies (rmat) WHERE rmat = TRUE;
CREATE INDEX idx_therapies_breakthrough         ON therapies (breakthrough_therapy) WHERE breakthrough_therapy = TRUE;
CREATE INDEX idx_therapies_orphan               ON therapies (orphan_drug) WHERE orphan_drug = TRUE;
CREATE INDEX idx_therapies_pediatric            ON therapies (pediatric_relevance) WHERE pediatric_relevance = TRUE;
CREATE INDEX idx_therapies_rare_disease         ON therapies (rare_disease) WHERE rare_disease = TRUE;

-- Full-text search across key fields
CREATE INDEX idx_therapies_fts ON therapies
    USING GIN (
        to_tsvector('english',
            coalesce(product_name, '') || ' ' ||
            coalesce(generic_name, '') || ' ' ||
            coalesce(brand_name, '') || ' ' ||
            coalesce(manufacturer, '') || ' ' ||
            coalesce(disease, '') || ' ' ||
            coalesce(indication_details, '')
        )
    );

-- JSONB indexes for array searching
CREATE INDEX idx_therapies_trial_identifiers    ON therapies USING GIN (trial_identifiers);
CREATE INDEX idx_therapies_fda_documents        ON therapies USING GIN (relevant_fda_documents);
CREATE INDEX idx_therapies_data_sources         ON therapies USING GIN (data_sources);

-- Composite index for common dashboard query pattern
CREATE INDEX idx_therapies_phase_status_active
    ON therapies (clinical_phase, fda_approval_status, is_active);
```

### 5.4 `therapy_milestones`

Tracks discrete milestone events in a therapy's development lifecycle. Supplements the JSONB `key_milestones` field on `therapies` with a normalized, queryable structure.

```sql
CREATE TABLE therapy_milestones (
    id                  UUID            PRIMARY KEY DEFAULT gen_random_uuid(),
    therapy_id          UUID            NOT NULL REFERENCES therapies (id) ON DELETE CASCADE,

    milestone_type      TEXT            NOT NULL,   -- e.g., "Phase 3 Start", "BLA Submission", "PDUFA Date", "Advisory Committee"
    expected_date       DATE,
    actual_date         DATE,
    description         TEXT,
    source_url          TEXT,
    is_completed        BOOLEAN         NOT NULL DEFAULT FALSE,

    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

-- Trigger
SELECT create_updated_at_trigger('therapy_milestones');

-- Indexes
CREATE INDEX idx_therapy_milestones_therapy_id      ON therapy_milestones (therapy_id);
CREATE INDEX idx_therapy_milestones_expected_date   ON therapy_milestones (expected_date)
    WHERE expected_date IS NOT NULL AND is_completed = FALSE;
CREATE INDEX idx_therapy_milestones_type            ON therapy_milestones (milestone_type);
CREATE INDEX idx_therapy_milestones_upcoming
    ON therapy_milestones (expected_date)
    WHERE is_completed = FALSE AND expected_date >= CURRENT_DATE;

ALTER TABLE therapy_milestones
    ADD CONSTRAINT fk_therapy_milestones_therapies
    FOREIGN KEY (therapy_id) REFERENCES therapies (id) ON DELETE CASCADE;
```

### 5.5 `therapy_version_history`

Immutable audit log of every change to a therapy record. Enables diffing between versions and rolling back specific fields.

```sql
CREATE TABLE therapy_version_history (
    id                  UUID            PRIMARY KEY DEFAULT gen_random_uuid(),
    therapy_id          UUID            NOT NULL REFERENCES therapies (id) ON DELETE CASCADE,

    -- changed_fields: array of field names that changed
    -- ["clinical_phase", "fda_approval_status"]
    changed_fields      JSONB           NOT NULL DEFAULT '[]',

    -- previous_values: map of field name to previous value
    -- {"clinical_phase": "phase_3", "fda_approval_status": "bla_nda_submitted"}
    previous_values     JSONB           NOT NULL DEFAULT '{}',

    -- new_values: map of field name to new value
    -- {"clinical_phase": "nda_bla_submitted", "fda_approval_status": "under_review"}
    new_values          JSONB           NOT NULL DEFAULT '{}',

    change_source       change_source   NOT NULL,
    changed_by_user_id  UUID            REFERENCES users (id) ON DELETE SET NULL,

    -- Source document or API call that triggered this change
    change_trigger      TEXT,           -- e.g., "clinicaltrials_ingestion_job_id", "user_manual_edit"
    change_notes        TEXT,

    changed_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()

    -- No updated_at: this table is append-only / immutable
);

-- Indexes
CREATE INDEX idx_therapy_version_history_therapy_id  ON therapy_version_history (therapy_id);
CREATE INDEX idx_therapy_version_history_changed_at  ON therapy_version_history (changed_at DESC);
CREATE INDEX idx_therapy_version_history_user        ON therapy_version_history (changed_by_user_id)
    WHERE changed_by_user_id IS NOT NULL;
CREATE INDEX idx_therapy_version_history_source      ON therapy_version_history (change_source);
CREATE INDEX idx_therapy_version_history_fields      ON therapy_version_history USING GIN (changed_fields);

ALTER TABLE therapy_version_history
    ADD CONSTRAINT fk_tvh_therapies
    FOREIGN KEY (therapy_id) REFERENCES therapies (id) ON DELETE CASCADE;
ALTER TABLE therapy_version_history
    ADD CONSTRAINT fk_tvh_users
    FOREIGN KEY (changed_by_user_id) REFERENCES users (id) ON DELETE SET NULL;
```

### 5.6 `data_source_records`

Stores raw and parsed records from each external data source ingestion run. Provides full provenance for every piece of data in the therapy record.

```sql
CREATE TABLE data_source_records (
    id                  UUID            PRIMARY KEY DEFAULT gen_random_uuid(),
    therapy_id          UUID            NOT NULL REFERENCES therapies (id) ON DELETE CASCADE,

    source_type         data_source_type NOT NULL,
    source_url          TEXT,           -- URL of the original document/page
    source_id           TEXT,           -- External identifier (e.g., NCT number, BLA number, PubMed ID)

    -- raw_data: the full API response or scraped content, as received
    raw_data            JSONB           NOT NULL DEFAULT '{}',

    -- extracted_data: normalized fields extracted from raw_data
    extracted_data      JSONB           NOT NULL DEFAULT '{}',

    extracted_at        TIMESTAMPTZ     NOT NULL DEFAULT NOW(),

    -- Confidence that this source record accurately represents the therapy
    confidence_score    SMALLINT        CHECK (confidence_score BETWEEN 0 AND 100),

    is_verified         BOOLEAN         NOT NULL DEFAULT FALSE,
    verified_by_user_id UUID            REFERENCES users (id) ON DELETE SET NULL,
    verified_at         TIMESTAMPTZ,

    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

-- Indexes
CREATE INDEX idx_data_source_records_therapy_id     ON data_source_records (therapy_id);
CREATE INDEX idx_data_source_records_source_type    ON data_source_records (source_type);
CREATE INDEX idx_data_source_records_source_id      ON data_source_records (source_id)
    WHERE source_id IS NOT NULL;
CREATE INDEX idx_data_source_records_extracted_at   ON data_source_records (extracted_at DESC);
CREATE INDEX idx_data_source_records_unverified
    ON data_source_records (therapy_id, extracted_at DESC)
    WHERE is_verified = FALSE;

-- Unique constraint: one record per (therapy, source_type, source_id, extraction_time)
CREATE UNIQUE INDEX uq_data_source_records_dedup
    ON data_source_records (therapy_id, source_type, source_id, extracted_at)
```

## 6. Row-Level Security Policies

Row-Level Security (RLS) is enabled on tables containing institution-scoped or user-scoped sensitive data. The application sets session-level configuration variables before executing queries. RLS provides a database-level backstop against application authorization bugs.

```sql
-- ============================================================
-- RLS SETUP
-- The application sets these at the start of each transaction:
--   SET LOCAL app.current_user_id     = '<user_uuid>';
--   SET LOCAL app.current_institution_id = '<institution_uuid>';
--   SET LOCAL app.current_user_role   = 'admin' | 'institution_admin' | 'user';
-- ============================================================

-- Helper functions for RLS policy expressions
CREATE OR REPLACE FUNCTION current_app_user_id() RETURNS UUID AS $$
    SELECT NULLIF(current_setting('app.current_user_id', true), '')::UUID;
$$ LANGUAGE SQL STABLE;

CREATE OR REPLACE FUNCTION current_app_institution_id() RETURNS UUID AS $$
    SELECT NULLIF(current_setting('app.current_institution_id', true), '')::UUID;
$$ LANGUAGE SQL STABLE;

CREATE OR REPLACE FUNCTION current_app_user_role() RETURNS TEXT AS $$
    SELECT NULLIF(current_setting('app.current_user_role', true), '');
$$ LANGUAGE SQL STABLE;

-- ── operational_readiness ──────────────────────────────────────────────────

ALTER TABLE operational_readiness ENABLE ROW LEVEL SECURITY;

-- Users can see all operational_readiness records for their own institution.
-- Admins can see all records.
CREATE POLICY or_select_policy ON operational_readiness
    FOR SELECT
    USING (
        institution_id = current_app_institution_id()
        OR current_app_user_role() = 'admin'
    );

-- Only institution_admin (within their institution) or admin can INSERT.
CREATE POLICY or_insert_policy ON operational_readiness
    FOR INSERT
    WITH CHECK (
        (institution_id = current_app_institution_id()
            AND current_app_user_role() IN ('institution_admin', 'user'))
        OR current_app_user_role() = 'admin'
    );

-- Only institution_admin (within their institution) or admin can UPDATE.
CREATE POLICY or_update_policy ON operational_readiness
    FOR UPDATE
    USING (
        institution_id = current_app_institution_id()
        OR current_app_user_role() = 'admin'
    );

-- ── institution_therapy_priorities ────────────────────────────────────────

ALTER TABLE institution_therapy_priorities ENABLE ROW LEVEL SECURITY;

CREATE POLICY itp_select_policy ON institution_therapy_priorities
    FOR SELECT
    USING (

        OR current_app_user_role() = 'admin'
    );

CREATE POLICY itp_insert_policy ON institution_therapy_priorities
    FOR INSERT
    WITH CHECK (
        (institution_id = current_app_institution_id()
            AND current_app_user_role() IN ('institution_admin', 'user'))
        OR current_app_user_role() = 'admin'
    );

CREATE POLICY itp_update_policy ON institution_therapy_priorities

        OR current_app_user_role() = 'admin'

ALTER TABLE operational_tasks ENABLE ROW LEVEL SECURITY;

-- Inherit institution isolation via join to operational_readiness

            SELECT 1 FROM operational_readiness or_
```

```sql
-- PostgreSQL built-in FTS using tsvector/tsquery.
-- Language: 'english' (stemming, stop words)
-- ============================================================

-- Materialized view for fast therapy search (refreshed after ingestion runs)
-- Combines all searchable fields into a single tsvector column.
CREATE MATERIALIZED VIEW therapy_search_index AS
SELECT
    t.id,
    t.product_name,
    t.generic_name,
    t.brand_name,
    t.manufacturer,
    t.disease,
    t.disease_category,
    t.clinical_phase,
    t.fda_approval_status,
    t.is_active,
    setweight(to_tsvector('english', coalesce(t.product_name, '')), 'A') ||
    setweight(to_tsvector('english', coalesce(t.generic_name, '')), 'A') ||
    setweight(to_tsvector('english', coalesce(t.brand_name, '')), 'B') ||
    setweight(to_tsvector('english', coalesce(t.manufacturer, '')), 'B') ||
    setweight(to_tsvector('english', coalesce(t.disease, '')), 'B') ||
```

### 9.2 Migration Rules

- **Never drop a column in a single migration.** Use a two-step approach: deprecate (stop writing), then drop in a later migration after all reads have been updated.
- **Never rename a column in a single migration.** Add the new column, backfill, migrate reads/writes, then drop the old column in a subsequent migration.
- **Enum additions are safe:** `ALTER TYPE ... ADD VALUE` is non-blocking in PostgreSQL 12+.
- **Adding NOT NULL columns:** Always add with a DEFAULT value or perform a three-step migration (add nullable → backfill → add NOT NULL constraint).
- **Index creation** on large tables: use `CREATE INDEX CONCURRENTLY` to avoid table locks.
- **Migrations run before new Cloud Run revision goes live** (via Cloud Build step); migrations must be backward compatible with the currently deployed application version.
